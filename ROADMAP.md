# СТРАТЕГИЧЕСКИЙ ПЛАН РАЗВИТИЯ И РОУДМАП WARLINK

Документ определяет архитектурный вектор развития клиентского приложения, серверной инфраструктуры и сетевых сервисов WarLink.

---

## 1. АРХИТЕКТУРНАЯ МОДЕРНИЗАЦИЯ UI/UX (VITE + SHADCN/UI + WAILS V3)

Масштабный переход от монолитного HTML/JS/CSS к компонентной архитектуре и нативному десктопному Go-рантайму.

### Фаза 1. Модульный фронтенд нового поколения (Vite + React / TS + Tailwind CSS + shadcn/ui)
- [ ] **Изоляция фронтенда и сохранение стабильности Go-ядра:**
  - Низкоуровневый сетевой стек Go (`sing-box`, `WinDivert`, `wintun.dll`, системный роутер, Hysteria 2) остается неизменным и надежным.
  - Разработка фронтенда выносится в отдельное модульное TypeScript-приложение на базе сборщика Vite с финальной сборкой в `ui/dist` (встраивание в Go через `embed.FS`).
- [ ] **Внедрение дизайн-системы shadcn/ui (Dark Cloudflare Utility):**
  - Полный отказ от монолитного `ui/index.html` и разрозненного CSS.
  - Использование эталонных открытых компонентов высшего качества:
    - `Tabs` — компактное, предсказуемое переключение серверов («Москва», «Франкфурт», «Транзит») и настроек.
    - `Dialog` / `Sheet` — аккуратные модальные окна тикетов, автодиагностики сети и доната без сдвигов верстки (Zero Layout Shift).
    - `DropdownMenu` / `Select` — выпадающие списки выбора профилей desync и сетевых адаптеров.
    - `Toasts (Sonner)` — легковесные информационные статусы подключения и копирования.
    - `Badge` / `Progress` — визуализация игрового уровня WARDOGS и статусов доступности слотов.
    - `Lucide Icons` — строгие векторные SVG-иконки с соблюдением правила Zero Emoji.
- [ ] **Реактивное состояние и отказ от DOM-манипуляций:**
  - Внедрение легковесного стейт-менеджера `Zustand` вместо тысяч строк ручных вызовов `document.getElementById` и `classList.toggle`.
  - Реактивная подписка на входящие события Server-Sent Events (SSE) и фиче-флаги.
- [ ] **Компактная графическая телеметрия:**
  - Интеграция микро-графиков задержки и джиттера (`Recharts` / `Tremor`) в режиме реального времени.

### Фаза 2. Нативная десктопная экосистема (Wails v3 Core)
- [ ] **Строго типизированный мост Go <-> TypeScript:**
  - Переход от самописного локального HTTP-сервера (`127.0.0.1:<port>`) к прямому IPC через Wails v3.
  - Автоматическая кодогенерация TypeScript-типов из Go-структур: компилятор гарантирует соответствие всех сетевых вызовов и моделей данных.
- [ ] **Глубокая интеграция с Windows 10/11:**
  - Полноценное управление системным треем (сворачивание в трей, контекстное меню быстрого переключения маршрутов, статус «В игре»).
  - Нативные системные push-уведомления Windows Action Center.
  - Бесшовное окно без системных рамок (frameless window) с кастомной шапкой в темном стиле.
- [ ] **Сверхнизкое потребление ресурсов:**
  - Оптимизация потребления оперативной памяти (<60 МБ в фоне) и холодный запуск менее чем за 300 мс.

## 2. СЕТЕВОЙ СТЕК И ИГРОВАЯ МАРШРУТИЗАЦИЯ

- [ ] **Облачные пресеты Zapret2 (`/api/v1/desync/config`):**
  - Поддержка динамического обновления аргументов `winws2.exe` с сервера без пересборки бинарника клиента.
  - Раздельные правила обхода DPI для голосовых протоколов (Discord Voice, TeamSpeak) и игровых API.
- [ ] **Epic Online Services (EOS) изоляция и туннелирование:**
  - Расширение списков игровых процессов и портов аутентификации EOS.
  - Предотвращение утечек сокетов при смене игровых лобби.
- [ ] **Интеллектуальный выбор шлюза (Smart Multi-Pathing):**
  - Автоматический выбор оптимального узла («Москва» или «Франкфурт») на основе текущего RTT и потерь пакетов на стороне провайдера игрока.
